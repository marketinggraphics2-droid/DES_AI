## AI Usage

IQDesk uses a pluggable AI provider-abstraction layer, giving each deployment flexibility over which AI model provider powers the system.

Supported providers include:

- OpenAI, including the GPT-4o family

- Anthropic Claude

- Google Gemini

- Azure OpenAI

- Local models through Ollama

The provider is selected and configured per instance. API keys are stored encrypted using AES-256-CBC, with only the last 4 characters shown in the UI.

For RAG and embeddings, IQDesk uses ChromaDB with isolated vector collections per company.

Because IQDesk supports external AI providers, data may be sent to the selected provider depending on the configured model. For private or air-gapped deployments, local AI through Ollama can be used.

## Deployment Model

IQDesk supports both cloud-hosted and self-hosted deployment models, but it is primarily designed as a self-hosted, per-client deployment.

The platform is fully containerized through Docker and can run on-premise, on a client-owned cloud server, or on a private VM.

The documented stack includes:

- MSSQL 2022

- ChromaDB

- Express backend

- Next.js frontend

- NGINX reverse proxy

- Let’s Encrypt SSL

Production images are published to GitHub Container Registry, with optional Watchtower auto-updates.

IQDesk can be cloud-hosted, but there is no managed multi-tenant SaaS billing model. It is deployed per client.

For fully private or air-gapped AI use cases, self-hosting combined with Ollama is the preferred deployment path.

## Helpdesk and Workflow Features

## Ticket Management

IQDesk provides a helpdesk workflow for managing customer, internal, or IT support tickets.

Tickets can be submitted, tracked, assigned, responded to, and resolved through the platform. Ticket data can also be used for analytics such as ticket volume, backlog aging, First Response Time, MTTR, SLA compliance, and reopen rate.

## SLA Management

IQDesk has partial SLA management support.

The current system supports SLA measurement and reporting, but does not yet include full SLA enforcement, proactive breach alerts, or escalation workflows.

What exists:

- dueDate, which is manual and optional

- respondedAt, which records the first-response timestamp and is frozen on the first staff reply

- resolvedTime

- SLA Compliance %, based on tickets resolved on or before the due date

- First Response Time

- MTTR

What does not currently exist:

- No SLA policy engine

- No auto-calculated targets by priority or category

- No proactive breach detection job

- No breach-warning alerts

- No escalation rules or workflows

- No dedicated “escalate” action in the automation engine

- The automation engine currently supports only:

- SET_FIELD

- BLOCK_SAVE

- TRIGGER_WEBHOOK

SLA breach email alerts appear in the roadmap under Phase 6, but are not yet implemented.

In summary, IQDesk supports SLA measurement and reporting, but SLA enforcement, breach alerts, and escalation are not yet available.

## Self-Service Portal

The self-service portal allows customers to submit and track tickets without requiring agent permissions.

Customers can also start live chats through the portal.

IQDesk also includes an embeddable JavaScript chat widget using widget.js and a /widget iframe. This widget can be added to external websites and can use an AI copilot as first-line support.

The AI copilot can provide RAG-grounded answers, support auto-ticket creation, and hand off conversations to human agents when needed.

Public PAR, or Property Acknowledgement Receipt, signing is also supported through a tokenized link.
